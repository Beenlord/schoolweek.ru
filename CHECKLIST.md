# Чеклист ручного тестирования (auth + профиль)

Ручная проверка функционала регистрации, авторизации, восстановления пароля и редактирования
профиля (`/me`). Страницы сейчас без стилей — только рабочий скелет форм, задача этого
чеклиста — проверить логику, а не внешний вид.

## Регистрация (`/register`)

- [ ] Заполнение всех полей и отправка формы создаёт пользователя и авторизует его (редирект на `/now`).
- [ ] Пустое имя / email / пароль — форма не отправляется, под полем видна ошибка.
- [ ] Email, который уже зарегистрирован, — ошибка уникальности email.
- [ ] Пароль и повтор пароля не совпадают — ошибка валидации пароля.
- [ ] Не выбран секретный вопрос или пустой ответ — ошибка валидации.
- [ ] Некорректный часовой пояс (не из списка IANA) — ошибка валидации `timezone`.
- [ ] Поле часового пояса предзаполнено автоопределённым таймзоном браузера.
- [ ] Уже авторизованный пользователь при заходе на `/register` редиректится на `/now`.

## Авторизация (`/login`)

- [ ] Верные email + пароль — авторизация и редирект на `/now`.
- [ ] Неверный email или пароль — общая ошибка, без указания, что именно неверно.
- [ ] Пустые поля — форма не отправляется, показаны ошибки валидации.
- [ ] Чекбокс «Запомнить меня» — после закрытия и повторного открытия браузера сессия сохраняется
      (проверяется по `remember_token` в БД и cookie).
- [ ] Уже авторизованный пользователь при заходе на `/login` редиректится на `/now`.
- [ ] Ссылки на `/register` и `/forgot-password` рабочие.
- [ ] Выход (`/logout`, кнопка «Выйти» на `/now` и `/me`) завершает сессию и редиректит на `/`.
- [ ] После выхода `/now` и `/me` снова редиректят на `/login`.

## Восстановление пароля (`/forgot-password`)

- [ ] Шаг 1: email существующего пользователя — переход к шагу 2, показывается его секретный вопрос.
- [ ] Шаг 1: несуществующий email — ошибка, шаг не переключается.
- [ ] Шаг 2: верный ответ на секретный вопрос — переход к шагу 3.
- [ ] Шаг 2: неверный ответ — ошибка, шаг не переключается.
- [ ] Шаг 3: новый пароль + подтверждение — пароль меняется, показывается сообщение об успехе.
- [ ] Шаг 3: пароль и подтверждение не совпадают — ошибка валидации.
- [ ] После смены пароля можно войти по новому паролю и нельзя — по старому.
- [ ] Прямой вызов `/api/password/reset` без прохождения шага 2 в этой же сессии — отклоняется
      с ошибкой («Сначала подтвердите ответ на секретный вопрос»).

## Профиль (`/me`)

- [ ] Страница доступна только авторизованным (гостя редиректит на `/login`).
- [ ] Форма предзаполнена текущими данными пользователя (имя, email, часовой пояс, секретный вопрос).
- [ ] Изменение имени / email / часового пояса / секретного вопроса сохраняется и видно после
      обновления страницы.
- [ ] Email, занятый другим пользователем, — ошибка уникальности (свой текущий email при этом
      сохранить можно, ошибки быть не должно).
- [ ] Смена пароля без текущего пароля — ошибка («current_password» обязателен при заполненном
      «password»).
- [ ] Смена пароля с неверным текущим паролем — ошибка.
- [ ] Смена пароля с верным текущим паролем и совпадающим подтверждением — пароль меняется, можно
      войти по новому паролю.
- [ ] Смена ответа на секретный вопрос — восстановление пароля после этого работает по новому ответу,
      старый ответ больше не подходит.
- [ ] Кнопка «Выйти» на `/me` завершает сессию.

## Офлайн и синхронизация (`/now`)

Требует собранного `npm run build` (в dev-режиме `navigateFallback`/precache Workbox себя ведут иначе) и
установки офлайн через браузер (или DevTools → Application → Service Workers → Offline). Только `/now`
должен работать офлайн — остальные страницы (`/login`, `/me` и т.п.) принципиально требуют сервера.

- [ ] Открыть `/now` онлайн хотя бы раз (чтобы service worker и IndexedDB успели закэшировать неделю).
- [ ] Включить офлайн-режим (DevTools → Network → Offline) и перезагрузить `/now` — страница открывается
      (не нативная ошибка браузера «нет интернета»), показан баннер «Офлайн — показаны последние
      сохранённые данные».
- [ ] Офлайн отредактировать содержимое дня (textarea, blur для сохранения) — правка отображается сразу,
      без ошибок в консоли.
- [ ] Вернуть сеть (DevTools → Network → снять Offline) — офлайн-правка автоматически уходит на сервер
      (видно в Network как `POST /api/days/batch`), после чего `GET /api/days/sync` подтягивает
      актуальное состояние.
- [ ] Перезагрузить `/now` после восстановления сети — офлайн-правка на месте и в БД (не потерялась и не
      осталась только в IndexedDB).
- [ ] Конфликт: отредактировать один и тот же день из двух вкладок — одну офлайн, другую онлайн (с более
      поздним временем правки) — при синхронизации побеждает более поздняя правка, ранняя не затирает её.
- [ ] `/login`, `/register`, `/me` офлайн не притворяются рабочими (закономерно падают/не открываются —
      это ожидаемо, не баг).

## Общее

- [ ] CSRF/сессия: все формы (Inertia-визиты и AJAX-запросы восстановления пароля) проходят без
      ошибки 419.
- [ ] Обновление страницы (`F5`) на `/now` и `/me` не разлогинивает и не сбрасывает данные.
